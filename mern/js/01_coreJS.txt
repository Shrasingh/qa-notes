4.What is Closure? Function + its lexical scope  
    a closure is when a function remembers and can access variables from its outer (lexical) scope, even after that outer function has finished running
    function outer() {
        let count = 0;
        return function inner() {
        count++;
        console.log(count);
    };
   }
   const fn = outer();
   fn(); // 1
   fn(); // 2
   Like: A locker (function), Stores secret (count),Even after leaving → access retained
   Why closures are used?✅ Answer:Data hiding
                                   State management
                                   Memoization
                                   A closure is a function that remembers and can access variables from its outer scope even after the outer function has finished executing.

8.PROTOTYPES -Every object has hidden property:[[Prototype]]
    Question-function Person(name) {
               this.name = name;
             }
             Person.prototype.sayHi = function () {
                console.log("Hi");
             };
             const p = new Person("A");
             p.sayHi();
             WHY works?Prototype chain lookup
    In JavaScript, every object has an internal hidden property:
    [[Prototype]] This is basically a link to another object.
    You can think of it like: “If I don’t have something, ask my prototype.”
       function Person(name) {
          this.name = name;
        }
        Person.prototype.sayHi = function () {
          console.log("Hi");
        };
        const p = new Person("A");
        p.sayHi();                 
    when you create the function- 
       function Person(name) { ... }
    JavaScript automatically creates:
       Person.prototype = {constructer: Person}
    you add a method 
       Person.prototype.sayHi = function(){
        console.log("Hi");
       };
    now:
      Person.prototype = {
        constructer: Person,
        sayHi: function(){...}
      }
    when you do new Person("A")
    this is imp part new does 4things behind the scenes:
    step1: create empty object
      const p = {};
    step2: link prototype
      p.[[prototype]] = Person.prototype;  
    step3:call constructer
      Person.call(p,"A");
      so now p = {name:"A"} 
    step4: Return object
      return p;
    why does p.sayHi() word? bcz of Prototype chain lookup  
    prototype chain visualization-
    p
    ↓ [[Prototype]]
    Person.prototype
    ↓ [[Prototype]]
    Object.prototype
    ↓
    null
    JavaScript uses delegation, not copying
    p does NOT copy sayHi
    It borrows it via prototype 
    instead of duplicating functions - bad (memory heavy)
    this.sayHi = function(){...}
    good shared via prototype
    one function shared across all instances
    If an object doesn’t have a property, JavaScript looks up the prototype chain until it finds it (or reaches null).
    The Core Difference- prototype: A property of functions (constructors)
                                    Used when creating objects with new
                         __proto__ :A property of all objects
                                    Points to the object’s internal [[Prototype]]
        prototype is used to build objects
        __proto__ is how objects access their prototype
    | Feature         | `prototype`              | `__proto__`                   |
    | --------------- | ------------------------ | ----------------------------- |
    | Where it exists | On functions             | On all objects                |
    | Purpose         | Define shared properties | Access object's prototype     |
    | Used by         | `new` keyword            | JS engine during lookup       |
    | Standard?       | Yes                      | Legacy (but widely supported) |
    function A() {}
    A.prototype // ✅ exists
    Avoid using __proto__ directly.
    Use:
    Object.getPrototypeOf(p)
    Object.setPrototypeOf(p, newProto)
