In Node.js, the Event Loop processes asynchronous operations in several phases. One of the most important phases is the Timer phase.
Let’s break the Timer phase in detail: what it is, why it exists, how it works internally, and its components.
1️⃣ What is the Timer Phase?
The Timer phase is the first phase of the Node.js event loop.
It is responsible for executing callbacks scheduled by:
setTimeout()
setInterval()
These functions schedule a callback after a specified delay.
Example:
setTimeout(() => {
  console.log("Hello after 2 seconds");
}, 2000);
This does NOT guarantee exact execution after 2000ms.
Instead it means:
"Execute the callback after at least 2000ms when the event loop reaches the timer phase."

  2️⃣ Why the Timer Phase Exists

JavaScript in Node.js is single-threaded, but Node.js needs to handle many asynchronous operations like:
HTTP requests
File system operations
Database queries
Delayed task
The Timer phase allows scheduling tasks for future execution without blocking the main thread.
Without timers:
You would need blocking delays
The server would freeze
Concurrency would collapse
Timers allow non-blocking delays.
Example bad design (blocking):
sleep(2000)
console.log("done")
Example Node.js design:
setTimeout(() => {
  console.log("done")
}, 2000)
Node.js continues doing other work while waiting.
3️⃣How the Timer Phase Works Internally
    Internally Node.js uses libuv.
    libuv implements the event loop and timers system.
    Internal Timer Process
1️⃣ User schedules a timer
setTimeout(callback, delay)

2️⃣ Node registers the timer in libuv timer queue

  3️⃣ The timer stores:
    callback function delay time start time

  4️⃣ When the event loop reaches the Timer phase:
          Node checks:Has the timer delay expired?
          If YES → callback moves to execution queue.
          If NO → wait for next loop.
  4️⃣ Components of the Timer Phase The Timer phase contains several internal structures.
  1️⃣ Timer Queue A queue of scheduled timers.
       Each timer has: expiration time,callback ,repeat flag (for interval)
Example structure:
Timer Queue
Timer 1 → expires at 2000ms
Timer 2 → expires at 500ms
Timer 3 → expires at 1000ms
Timers are executed when their time has passed.
2️⃣ Expired Timer Detection
Node compares:
current_time >= timer_expiration_time
Example:
Timer: 1000ms
Current: 1100ms

→ timer is ready.

3️⃣ Callback Execution Queue
When timers expire:
Their callbacks move to the callback execution queue.
Example:
[callback1, callback2, callback3]
These callbacks are executed in FIFO order.

  After executing:
  Node re-registers the timer again with the same delay.

2️⃣ How Node.js Stores Timers Internally (libuv)
Timers are implemented by libuv, the async engine behind Node.js.
Node uses a data structure optimized for fast timer lookup.
Core structure
Internally libuv uses a Min Heap (Priority Queue).
Heap property:
Parent node expiration ≤ child expiration
So the earliest timer is always at the root.
Timer Structure
Each timer contains:
uv_timer_t
│
├── callback
├── timeout
├── repeat
├── start time

Example:

Timer A → 500ms
Timer B → 200ms
Timer C → 1000ms

Heap representation:

        B(200)
       /     \
   A(500)   C(1000)

Root always executes first.

Timer Registration Flow

When this runs:

setTimeout(callback, 1000);

Process: JavaScript API
            ↓
Node timers module
↓
libuv timer registration
↓
insert into min heap

Pseudo representation:

heap_insert(timer)

Complexity:

Insertion: O(log n)
Peek: O(1)
Removal: O(log n)
Timer Execution Flow
Each event loop iteration:
current_time = now()
while (heap_root.expiration <= current_time)
    execute callback
    remove timer
This ensures only expired timers execute.

setInterval Internals

For:

setInterval(fn, 1000);

libuv performs:

execute callback
↓
next_expiration = now + repeat
↓
reinsert timer into heap

So intervals are just repeating timers.
