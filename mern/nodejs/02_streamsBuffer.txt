Q8. What is cork() and uncork() in writable streams?
      cork() → buffer multiple writes
      uncork() → flush them together
      👉 Optimizes performance by batching writes
       What are cork() and uncork()?
    In a Writable stream (like a file stream or HTTP response), these two methods control when data is actually sent out.
    🔹 cork() Temporarily buffers (holds) all write() calls  Nothing is sent immediately
    🔹 uncork() Flushes all buffered data at once Sends everything in a single batch
    👉 This reduces the number of actual I/O operations, which makes things faster and more efficient
    ⚡ Why is this useful? Normally:stream.write("A");stream.write("B");stream.write("C");
    👉 This could trigger 3 separate writes (slow 😬)
    With cork():stream.cork(); stream.write("A");stream.write("B");stream.write("C");stream.uncork();
    👉 Now it's 1 batched write 
    Example (Q8-style answer)Here’s a clean exam-style example:
    const fs = require("fs");
    const writable = fs.createWriteStream("output.txt");
    // Start buffering
    writable.cork();
    writable.write("Hello ");
    writable.write("World ");
    writable.write("!!!");
    // Flush all at once
    writable.uncork();
    ✅ What happens here?
    All three write() calls are buffered
    Nothing is written immediately
    When uncork() is called → everything is written in one go
    🔍 Real-world analogy
    Think of it like sending messages:
    ❌ Without cork → sending 10 separate WhatsApp messages
    ✅ With cork → typing everything → sending one message
    💡 Bonus Tip (important!)
    If you forget to call uncork():
    Node.js will automatically flush on next tick But it's best practice to call it manually for control
    👉 cork() buffers multiple writes, and uncork() flushes them together to improve performance by reducing I/O operations.
