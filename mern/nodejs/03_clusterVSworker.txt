1. problem with nodejs is - single threaded(main thread)
                            uses event loop for async i/o 
                            it is good for - apis, db calls, network
                            but bad for cpu heavy tasks(image processing,hashing,loops)
        for ex - while(true){} // block everything
        so we need - parallelism
                     multi core usage
                     that's where cluster,worker threads


2. cluster(multi process)- multiple nodejs processes(forks)


       each process - has its own memory
                      has its own event loop
                      runs on separate CPU core
                      uses cluster module

                      Master Process
     |
                 ---------------------
                  |     |     |      |
                  W1    W2    W3     W4
        master creates worker using fork()
        all worker share same port(via os load balancing) 
    *multi-process model 
    *no share memory
    *IPC(inter process communication) required
    *good for scaling servers   

    WHEN TO USE cluster? when
          we want to handle more requests
          CPU has multiple cores
          stateless apis
          ex - express server scaling    
    LIMITATIONS - memory duplication(each process heavy)
                  IPC is slow
                  not good for shared state       



3. worker thread(multi thread) - worker threads - multiple threads in same process
         introduces to solve CPU heavy tasks
         how it works - 
              Main Thread
                  |
            ----------------
            |      |       |
           WT1    WT2     WT3    
           . all threads share : 
                 . memory
            . communication:
                  . message passing 
                  . SharedArrayBuffer     
        . multi threaded 
        . shared memory possible
        . faster than cluster(no process over head)   
        . best for cpu heavy tasks   

        WHEN TO USE WORKER THREAS?
          1.heavy computation(hashing compression ML) 
          2.need shared memory
          3.avoid blocking event loop

5. QUES
     1. Load balancing in cluster - round robin(default in modern node)
                                        Requests are sent one-by-one in order to each worker
                                        Like: Worker1 → Worker2 → Worker3 → repeat
                                    OS-level scheduling
                                        OS decides which worker gets the request
                                        Less predictable
                                    it matters - prevents overload on one worker
                                                 improve performance+response time

     2. Shared Memory(Worker threads) -  
           const shared = new SharedArrayBuffer(4);
           enables real parallel algorithms
           used in high performance system
          normally Threads/processes dont share memory,they communicate by copying data
          but with const shared = new SharedArrayBuffer(4);
          multiple threads can access the same memory directly
          why its powerfull - no copying faster,enables true parallel computing
            imp - we must handle race conditions,synchronizations(like locks)
                  tools - Atomics in javascript
             
      3.WORKER pool- instead of creating threads repeatedly(bcz it is expensive) use pool(like thread pool),libraries like Piscina
              Create a fixed number of workers
              Reuse them for tasks
      4. Fault Tolerance (Cluster)- if a worker crashes -> system should recover automatically.

Why doesn’t Node.js use threads by default like Java?

✅ Answer:

Threads introduce:
synchronization issues
memory overhead

🧪 Q9: PRACTICAL CODING
👨‍💻 Interviewer:

Write a small example using Worker Threads

✅ Answer:
const { Worker } = require('worker_threads');

const worker = new Worker(`
  const { parentPort } = require('worker_threads');
  parentPort.postMessage(2 + 2);
`, { eval: true });

worker.on('message', (msg) => {
  console.log(msg);
});
🔥 Follow-up:

Is this efficient for many tasks?

👉 Answer:

❌ No → create worker pool
