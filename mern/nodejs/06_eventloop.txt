11. Event Loop = mechanism that allows Node.js (single-threaded) to handle multiple operations asynchronously
    Node js is - single threaded(only one stack) but needs to handle APIs,DB calls,file system, timers,
     if everything was synchronous server would block so  node uses- call stack(main thread),web apis(background),event loop(scheduler)


2. How Event Loop Works (Core Idea) 
      Think of it like a manager:Run sync code (stack) 
      Offload async tasks to background (libuv)
      When done → put callbacks into queues
      Event loop picks and executes them   


3.  Internal Components
       🔹 1. Call Stack Executes synchronous code
       2. libuv (C++ layer) Handles: File I/O Networking Thread pool
       3. Queues Different queues: Microtask queue, Timer queue, I/O queue, Check queue 


4.  Event loop phases - node event loop runs in phases:
       1. Timers
       2. Pending callbacks (I/O)
       3. Idle/prepare
       4. Poll (I/O)
       5. Check (setImmediate)
       6. Close callbacks    
       order - SYNC
                 ↓
               process.nextTick - executed before everything else even before promises Special queue: nextTick queue
                 ↓
               Promise microtasks - runs after nextTick part of microtask queue :   AFTER EVERY PHASE: NODE RUNS NEXTTICK QUEUE MICROTASK QUEUE  
                 ↓
               Timers (setTimeout) - runs in timers phase 
                 ↓
               I/O callbacks - runs in poll phase
                 ↓
               setImmediate - runs in check phase
                 ↓
               close events - 
        *setTimeout- time phase
        *setImmediate - check phase
        it depends on context which(setImmediate,setTimeout) runs first - inside I/O setImmediate runs first,outside not guaranteed
5.  Diff bw nextTick vs setImmediate - nextTick(nextTick Special queue,highest Priority ,starvation risk)
               setImmediate(check phase,lower Priority,no starvation risk)

6.  Node uses 1 main thread ,libuv thread pool(4 by default)
7.  Eventloop(manager), Queues(waiting rooms), Priority-nextTick VIP <- Promise VIP <- Timers <- IO <- Immediate
8.  "Node.js event loop is a single-threaded mechanism that manages asynchronous operations by offloading tasks to libuv and executing callbacks in prioritized phases using queues like microtasks and macrotasks.



9.   Starvation - function loop(){
                     process.nextTick(loop);
                   }
                   loop();
        event loop gets blocked(starvation)
        nextTick keeps adding itself,Event loop never reaches timers or I/o
        Recursive process.nextTick causes starvation because it blocks the event loop from moving to other phases        


10.  Node.js event loop executes synchronous code first, then processes microtasks like Promises and nextTick, and then executes macrotasks across phases like timers, poll, and check. process.nextTick has the highest priority and can cause starvation if abused.

12- timers - phase is where node.js executed callbacks of funtions like setInterval setTimeout
             it checks which timers have completed their minimum delay then executes their callbacks.
             setTimeout(fn, 0) does NOT mean immediate execution
              It means:“Run this after at least 0ms, when event loop reaches timers phase
              1. setTimeout(()=>{
                console.log("Hellow");
              },1000);
              2.nodejs :  register this timer 
                        send it to libuv(c++layer)
              3.after 1000ms passes,callbacks to call stack 
              4.when event loop enters timers phase: it check all ready timers
                                                     pushes their callbacks to call stack 
               👉 Think of it like a kitchen timer ⏲️
               You set timer: “Cook after 10 minutes”
               Chef DOESN’T keep watching it continuously
               After 10 minutes → bell rings 🔔
               Chef processes it when free
               👉 Same in Node.js:
               Timer finishes → waits for event loop turn
               setTimeout(()=>{
                console.log("Hi");
               },1000); it means run after 1000ms but only when event loop is free 
               setTimeout(() => console.log("Timer"), 0);
               while(true) {} output nothing prints - event loop is blocked never reaches timers phase
               Timers phase executes callbacks of setTimeout and setInterval after their minimum delay has passed. However, execution depends on event loop availability, so delays are not guaranteed to be exact.
13- idle -phase is an internal phase used by nodejs/libub for housekeeping tasks. it is not directly accessible to developers and does not execute user callback
          Idle phase is an internal phase in Node.js event loop used by libuv for housekeeping and preparation tasks. It does not execute any user-defined callbacks
          it is part of "idle prepare" phases in libuv before entering poll phase to decide how lomg to block wait 
          it’s internal, not relevant to user code.
14.pending - The pending callbacks phase executes callbacks of certain system-level operations that were deferred from the previous loop iteration.
             It runs callbacks for some I/O operations that:
             were completed earlier but not executed immediately and are now waiting to be processed
             not all async callback go here this phase mainly handles TCP errors, some system level I/O callback
             deferred errors
             Some operations finish in poll phase, but instead of executing immediately:Node says“Let’s process this in next loop cycle safely”That “next cycle execution” happens in: pending callbacks phase
16. check -  this check phase executes callbacks scheduled by setImmediate()
              “Check phase executes callbacks scheduled via setImmediate(), and it runs immediately after the poll phase.”

17.close callback- The close callbacks phase executes callbacks for resources that have been closed, such as sockets or streams.
                   It runs cleanup callbacks when something is closed/destroyed Example socket closed file stream closed network connections closed 
                   const net = require("net");
                   const server = net.createServer((socket) => {
                    socket.on("close", () => {
                       console.log("Socket closed");
                       });
                      socket.destroy(); // force close
                       });
                     server.listen(3000);
                    when socket is destroyed close event callback runs in close callbacks phase
                    close callbacks run when resource is explicitly closed (socket.destroy())
                    or abruptly terminated(errors etc)
                    this phase ensures - resources are cleaned properly no memory leaks final lifecycle events are handled
                   “Close callbacks phase executes callbacks for resources like sockets or streams when they are closed or destroyed.”
            setTimeout →“Cook this after 10 minutes”
            setImmediate → “Do this right after you finish current orders”
