11. Event Loop = mechanism that allows Node.js (single-threaded) to handle multiple operations asynchronously
    Node js is - single threaded(only one stack) but needs to handle APIs,DB calls,file system, timers,
     if everything was synchronous server would block so  node uses- call stack(main thread),web apis(background),event loop(scheduler)


2. How Event Loop Works (Core Idea) 
      Think of it like a manager:Run sync code (stack) 
      Offload async tasks to background (libuv)
      When done → put callbacks into queues
      Event loop picks and executes them   


3.  Internal Components
       🔹 1. Call Stack Executes synchronous code
       2. libuv (C++ layer) Handles: File I/O Networking Thread pool
       3. Queues Different queues: Microtask queue, Timer queue, I/O queue, Check queue 


4.  Event loop phases - node event loop runs in phases:
       1. Timers
       2. Pending callbacks (I/O)
       3. Idle/prepare
       4. Poll (I/O)
       5. Check (setImmediate)
       6. Close callbacks    
       order - SYNC
                 ↓
               process.nextTick - executed before everything else even before promises Special queue: nextTick queue
                 ↓
               Promise microtasks - runs after nextTick part of microtask queue :   AFTER EVERY PHASE: NODE RUNS NEXTTICK QUEUE MICROTASK QUEUE  
                 ↓
               Timers (setTimeout) - runs in timers phase 
                 ↓
               I/O callbacks - runs in poll phase
                 ↓
               setImmediate - runs in check phase
                 ↓
               close events - 
        *setTimeout- time phase
        *setImmediate - check phase
        it depends on context which(setImmediate,setTimeout) runs first - inside I/O setImmediate runs first,outside not guaranteed
5.  Diff bw nextTick vs setImmediate - nextTick(nextTick Special queue,highest Priority ,starvation risk)
               setImmediate(check phase,lower Priority,no starvation risk)

6.  Node uses 1 main thread ,libuv thread pool(4 by default)
7.  Eventloop(manager), Queues(waiting rooms), Priority-nextTick VIP <- Promise VIP <- Timers <- IO <- Immediate
8.  "Node.js event loop is a single-threaded mechanism that manages asynchronous operations by offloading tasks to libuv and executing callbacks in prioritized phases using queues like microtasks and macrotasks.



9.   Starvation - function loop(){
                     process.nextTick(loop);
                   }
                   loop();
        event loop gets blocked(starvation)
        nextTick keeps adding itself,Event loop never reaches timers or I/o
        Recursive process.nextTick causes starvation because it blocks the event loop from moving to other phases        


10.  Node.js event loop executes synchronous code first, then processes microtasks like Promises and nextTick, and then executes macrotasks across phases like timers, poll, and check. process.nextTick has the highest priority and can cause starvation if abused.
