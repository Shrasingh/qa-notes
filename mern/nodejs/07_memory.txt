1. MEMORY LEAK-
  a memory leak happens when our program keeps using memory but never releases it even when its not longer needed
  over time memory usage keeps increasing until the app becomes slow or crashes
  for ex- we keep taking plates from the kitchen and never returning them,even if we stop eating but plate stays with usage
  eventually the kitchen runs out of the plates:
  so if objects are still referenced ,GC collector can not remove them - memory leak
  normal memory lifecycle - object created,used by the program,no referenced remain,gc removes it 
  leak situation - object created, program finished using it,references stil exists,gc cannot remove it 



2. HOW MEMORY WORKS IN NODEJS
  nodejs uses V8 engine which manages memory automatically using garbage collector
  GC frees memory only when objects are unreachable
   ex - let user = {name: "Shraddha"};
     user = null;
     now object is reachable -> GC removes it.
     but if something still refernced it GC cannot remove it-> memory leak

9. BEST PRACTICES TO AVOID MEMORY LEAKS
    avoid global variables
    use WeakMap/WeakSet(weak references allow GC)
    limit cache size(use lru cache,redis)
    remove event listeners- emitter.removeListener()
    clear times - clearTimeout(cancels a setTimeout() ;stops a one-time delayed function)
                  clearInterval(cancel a setInterval() ; stops a repeating function)
    avoid large closures
    monitor memory regularly 
    ⏰ setTimeout + clearTimeout
    Think of ordering food with a delay.
    You tell the restaurant: “Bring my food after 30 minutes.”
    But after 10 minutes you change your mind and say “Cancel the order.”
    So the food never comes.
    👉 That cancellation is like clearTimeout() — it cancels a one-time scheduled action.
    Code example
    let order = setTimeout(() => {
     console.log("Food delivered");
    }, 30000);
    clearTimeout(order); // order cancelled
     🔔 setInterval + clearInterval
   Think of an alarm clock that rings every morning.
   Alarm rings every day at 7 AM.
   After a few days you turn the alarm off.
   👉 Stopping that repeating alarm is like clearInterval() — it cancels a repeating action.
   Code example
   let alarm = setInterval(() => {
   console.log("Wake up!");
    }, 5000);
    clearInterval(alarm); // stop the repeating alarm
    ✅ Super short memory trick 
   clearTimeout → cancel ONE future event (food order)
   clearInterval → stop REPEATING events (alarm clock)

11.1️⃣ Why Closures Cause Memory Leaks Concept
    A closure keeps a reference to variables from its outer scope even after the outer function finishes execution.
    Because references still exist, the garbage collector cannot remove those objects.
    Example
       function createLogger() {
       const largeData = new Array(1000000).fill("memory");
       return function log() {
        console.log("Logging...");
       };
     }
    const logger = createLogger();
    Problem
    Even though largeData is not used anymore:
    closure → references outer scope So largeData remains in memory.
    Visualization
    logger()
      ↑
    closure
      ↑
    outer function scope
      ↑
    largeData array
    GC cannot remove largeData.
    Fix - Avoid storing large objects inside closures.
    function createLogger() {
    return function log() {
        console.log("Logging...");
    };}
   2️⃣ How V8 Garbage Collection Works
   The V8 JavaScript Engine uses automatic garbage collection.
   Main Idea
   Garbage Collector removes objects that are unreachable.
   Example
   let user = {name:"Shraddha"};
   user = null;
   Now the object has no references, so GC deletes it.
   Steps
          1. Mark Phase
             GC starts from root objects:global,stack variables,closures 
             Then marks reachable objects.

          2. Sweep Phase Unmarked objects are garbage → removed.
          3. Compact Phase Memory is reorganized to remove fragmentation.
    3️⃣ What is Generational Garbage Collection
       V8 assumes:Most objects die young. So memory is split into two generations.
       Young Generation-Stores new objects.
      Algorithms:Scavenge GC
                 Minor GC

        Example:temporary variables
                request objects
                 short-lived data
      Old Generation
      Stores long-lived objects.
      Algorithms:Mark-SweepMark-Compact
    Example: caches, global variables, long-lived objects
    Why This Is Fast
     Because GC runs frequently on young objects only, improving performance.

    7️⃣ Retained Size vs Shallow Size These terms appear in heap snapshot analysis.
        Shallow Size -Memory used by the object itself.
                Example: Object = 64 bytes 
        Retained Size-Total memory that would be freed if the object is removed.
        Includes: object,children,references
        Example- Cache object→ holds array→ array holds 1000 objects
                 Retained size = all memory of that structure.
    8️⃣How Redis Prevents Memory Leaks in Caching Systems Instead of storing cache in application memory, companies use Redis. Why?
        Node memory is limited.
        Example:~1.5GB heap limit
        Redis solves: unbounded in-memory cache Redis Eviction Policies
         Examples:LRU (least recently used),LFU,TTL expiration
         Example:SET user:1 "data" EX 60
          After 60 seconds → removed automatically.
    9️⃣ What Happens When Heap Limit is Exceeded
       Default Node heap limit:~1.5GB (64-bit) If exceeded:
       FATAL ERROR: CALL_AND_RETRY_LAST Allocation failed
       JavaScript heap out of memory
       Server crashes.Increase limit 
       node --max-old-space-size=4096 app.js
       Now:4GB heap
       But this does not fix leaks, only delays crash.
    🔟 Why Microservices Reduce Memory Leak Risk

      If one service leaks memory → only that service restarts.
