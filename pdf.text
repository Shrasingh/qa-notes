“I built a production-ready invoice system where the frontend controls layout and the backend controls rendering and distribution.

The React frontend is built using npm run build.
The backend (Express) serves this build as static files, so the app runs as a single deployable service.

When a user creates an invoice, the frontend generates a unique slug and sends the entire invoice form object to
POST /api/invoice/save.

The backend stores this invoice data temporarily in memory (cache with TTL).
This data is ephemeral — it only exists to support preview and PDF generation, so we avoid unnecessary DB writes.

When the user clicks “Generate PDF”, the frontend opens
GET /api/invoice/pdf/:slug.

The backend uses Puppeteer to load the actual frontend invoice page (/internal-invoice/:slug), waits for React, data, and fonts to fully render, and then generates a pixel-perfect PDF.

The generated PDF is:

returned immediately to the user

uploaded asynchronously to Google Drive, with the target folder decided by business rules (store code).

This approach avoids duplicate templates, guarantees visual consistency, and scales cleanly.”


Q1: Why not generate PDFs using backend HTML templates?

Answer:

“Using frontend rendering guarantees pixel-perfect consistency.
Any UI change automatically reflects in the PDF, and we avoid maintaining duplicate templates.”

❓ Q2: Why cache invoice data instead of saving directly to DB?

Answer:

“PDF generation is a short-lived operation.
Caching avoids unnecessary DB writes, improves latency, and keeps persistence separate from rendering.”

❓ Q3: What happens if the server crashes before PDF generation?

Answer:

“In production, the in-memory cache would be replaced with Redis.
This allows recovery, horizontal scaling, and fault tolerance.”

❓ Q4: How does this system scale?

Answer:

“Stateless APIs, Redis for cache, containerized Puppeteer workers, and async Drive uploads.
PDF generation can be offloaded to a job queue if volume increases.”

❓ Q5: Why upload PDFs asynchronously?

Answer:

“The user experience should not depend on third-party storage latency.
We return the PDF immediately and upload in the background.”

❓ Q6: How do you secure Google Drive access?

Answer:

“OAuth2 with refresh tokens stored in environment variables.
No secrets are hard-coded, and permission errors are explicitly handled.”

❓ Q7: Why render frontend URLs instead of raw HTML strings?

Answer:

“Rendering real URLs ensures React lifecycle, API calls, fonts, and CSS behave exactly as in production.”

❓ Q8: What would you improve next?

Answer:

“Move cache to Redis, add retryable background jobs for uploads, and introduce audit logging for invoices.”
